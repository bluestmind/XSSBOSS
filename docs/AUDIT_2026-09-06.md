**XSSBOSS audit — 6 September 2026**

My assessment: this is a substantial research prototype with useful engineering foundations, but I would not approve the supplied stack for a shared or externally reachable deployment yet. The largest immediate gains are trustworthy evidence, isolation, and reproducible evaluation. The repository does not establish a real-world detection or bounty acceptance rate, and it cannot justify a “highest win rate” claim.

Scope: static inspection of the current working tree, including API security, diagnostic logging, evidence storage, deployment, selected worker lifecycle code, benchmark scoring, CI, UI integration, and selected collector components. HEAD was `54e9381a`; 106 tracked paths already had changes at the status snapshot. References describe the reviewed working files, not necessarily that commit. This is not an exhaustive assurance review of every file; bundled third-party projects, captured target evidence, live deployments, and external targets were not audited.

**Checks actually completed**

- Nine selected existing backend tests passed: production configuration, diagnostic logging, and two accuracy gate tests. These are narrow regression checks, not evidence that the issues below are absent. Pytest reported a cache-directory permission warning.
- The UI production build passed, including TypeScript compilation. Strict UI lint passed.
- `pip check` found no dependency compatibility conflicts. That command does not check security advisories. Installed versions confirmed Starlette 0.27.0, python-multipart 0.0.6, FastAPI 0.104.1, and Playwright 1.40.0.
- No scans, browser exploitation tests, or vulnerability reproductions were run. The full test suite and hosted CI were not run. No application source was changed; this report was added and the UI build generated its normal output.

Priority P1 means address before shared deployment or before relying on the affected accuracy claim. P2 means address in the next engineering pass. Findings are based on source inspection unless a completed check is explicitly identified. Exploitability of a deployed system depends on its actual network and authentication configuration.

**Findings and modifications**

1. **P1 — The supplied reverse proxy grants API credentials without authenticating the visitor.** [Nginx configuration](F:/projects/XSSBOSS/deploy/nginx.conf:6) supplies the backend API key on every proxied API request. [Compose](F:/projects/XSSBOSS/compose.production.yml:103) publishes the UI port without a loopback bind, and the supplied stack has no visitor authentication layer. Someone who can reach that entry point can be treated as the default API tenant. An independently configured outer access gateway could restrict this, but it is not part of the reviewed deployment. **Modify:** authenticate users at the entry point and derive tenant identity from their authenticated session. Remove unconditional shared-key injection. Until that exists, constrain the listener and ingress to the intended operator boundary. Acceptance criterion: an unauthenticated visitor has no data or operation access, while separate users retain separate tenant identities.

2. **P1 — Docker builds can package local secrets and captured data.** [Dockerfile](F:/projects/XSSBOSS/Dockerfile:7) copies the whole workspace into the API image. [.dockerignore](F:/projects/XSSBOSS/.dockerignore:1) excludes some generated files but does not exclude `.env`, environment variants, `evidence/`, browser profiles, or SQLite journal sidecars. Those categories exist in this workspace; their secret contents were not inspected. **Modify:** explicitly copy required application directories, exclude private and generated data from build contexts, and inject runtime secrets outside image layers. Verify the resulting image file inventory before distribution. If an earlier image was shared, assess which secrets it actually contained and rotate affected credentials.

3. **P1 — Diagnostic logs escape tenant isolation.** [LogEvent](F:/projects/XSSBOSS/backend_api/models/log_event.py:7) has no tenant field or ownership relationships; it is absent from the [ORM isolation map](F:/projects/XSSBOSS/backend_api/tenancy.py:36). [Log queries and deletion](F:/projects/XSSBOSS/backend_api/services/log_service.py:185) therefore are not restricted by that map. Export and live delivery also lack an ownership boundary in the [logs router](F:/projects/XSSBOSS/backend_api/routers/logs.py:51). Consequences include cross-tenant disclosure and deletion of diagnostic records. **Modify:** attach immutable tenant ownership to diagnostic events and enforce it for reads, statistics, exports, writes, deletion, and streaming. Keep system-only logs in an explicitly privileged channel. Validate supplied experiment and target IDs against that owner.

4. **P1 — Removing a configured tenant token does not revoke its stored access.** [Provisioning](F:/projects/XSSBOSS/backend_api/services/tenant_service.py:29) updates configured tenants and marks them active, but does not deactivate tenants removed from configuration. [Authentication](F:/projects/XSSBOSS/backend_api/services/tenant_service.py:40) accepts any matching active database record. This matters when another configured token keeps authentication enabled. **Modify:** define an explicit credential revocation lifecycle and make configuration reconciliation honor it. Verify rotation, removal, disablement, and restart behavior. Preserve tenant data according to retention policy separately from access revocation.

5. **P1 — CORS accepts every HTTP and HTTPS origin.** [Middleware](F:/projects/XSSBOSS/backend_api/main.py:244) uses an unrestricted origin regex alongside the configured allowlist and enables credentials. The regex defeats the intended origin restriction even though production validation requires configured origins. **Modify:** use a precise environment-specific allowlist and only enable credentialed browser requests where needed. Validate rejection of unapproved and opaque origins. CORS is an additional browser boundary; it does not replace authentication.

6. **P1 — Installed upload dependencies have published security defects.** [Requirements](F:/projects/XSSBOSS/backend_api/requirements.txt:2) pin Starlette 0.27.0 and [python-multipart 0.0.6](F:/projects/XSSBOSS/backend_api/requirements.txt:18). These installed versions fall within affected ranges for published denial-of-service advisories: [Starlette advisory](https://github.com/Kludex/starlette/security/advisories/GHSA-f96h-pmfr-66vw) and [python-multipart advisory](https://github.com/Kludex/python-multipart/security/advisories/GHSA-59g5-xgcq-4qw3). The project uses multipart parsing in the [Burp import handler](F:/projects/XSSBOSS/backend_api/routers/burp.py:159), so this is not merely an unused dependency observation. **Modify:** upgrade the FastAPI/Starlette/multipart stack together to compatible, currently maintained releases; resolve and audit the complete dependency set; enforce application request limits. The versions that fixed these two historical advisories are not a complete recommendation for a current secure version set.

7. **P1 — Evidence marked as credential-redacted can still contain secrets.** [Request redaction](F:/projects/XSSBOSS/backend_api/services/evidence_service.py:40) covers selected headers and cookies, but leaves URL parameters and request bodies unchanged. [Response registration](F:/projects/XSSBOSS/backend_api/services/evidence_service.py:131) stores response headers unchanged; logs and DOM snapshots are also persisted as supplied. Meanwhile request metadata declares `credentials_redacted=True`. **Modify:** use one structured redaction policy across URLs, bodies, nested data, request and response headers, logs, and exports. Record the policy version and limitations accurately. Treat screenshots and DOM artifacts as sensitive even after text redaction, and apply encryption, access control, and retention to them.

8. **P1 — Standard Python logging bypasses the structured redactor.** [PythonLogHandlerBridge](F:/projects/XSSBOSS/backend_api/services/log_service.py:289) sends formatted messages and exception text directly to the ring buffer, whereas `LogService.emit` sanitizes its inputs. Passing redaction tests for `emit` therefore does not protect the bridge. [Logging setup](F:/projects/XSSBOSS/backend_api/utils/logger.py:8) also installs a standard output handler. **Modify:** sanitize at every final output boundary, including bridge events and process logs, before storage or broadcast. Test nested credentials and exception text as well as structured dictionaries.

9. **P1 — Browser workers have an unnecessarily large security exposure.** The [browser image](F:/projects/XSSBOSS/Dockerfile:11) inherits a root-running image without a non-root user declaration. [Browser options](F:/projects/XSSBOSS/browser_workers/selenium_config.py:14) explicitly disable the Chromium sandbox; [another launch path](F:/projects/XSSBOSS/browser_workers/executor.py:258) does the same. [Compose](F:/projects/XSSBOSS/compose.production.yml:73) supplies workers the shared backend environment, including platform secrets. These processes load untrusted page content. **Modify:** use a non-root, sandbox-compatible runtime, minimum privileges, restricted mounts and egress, resource limits, and narrowly scoped worker credentials. Playwright's [official Docker guidance](https://playwright.dev/python/docs/docker) recommends a separate user and an appropriate seccomp profile for untrusted browsing.

10. **P1 — Default public proxy use and disabled certificate checks weaken confidentiality and evidence integrity.** [Configuration](F:/projects/XSSBOSS/backend_api/config.py:100) enables proxy use by default; [startup](F:/projects/XSSBOSS/backend_api/main.py:128) starts a harvester that obtains public proxies. [Browser contexts](F:/projects/XSSBOSS/browser_workers/executor.py:430) ignore HTTPS errors, and [connectivity checks](F:/projects/XSSBOSS/backend_api/utils/stealth.py:333) disable certificate verification. This permits untrusted intermediaries to affect sensitive traffic or observations, depending on the selected route. **Modify:** disable automatic public proxy acquisition by default, permit only operator-approved intermediaries, and validate TLS. For an approved interception proxy, install its explicit CA instead of disabling verification globally. Record transport configuration with evidence.

11. **P1 — The collector's private-network setting is not enforced.** [ScopePolicy](F:/projects/XSSBOSS/xssboss-collector/src/xsscollector/scope.py:75) stores `allow_private_networks`, but [destination validation](F:/projects/XSSBOSS/xssboss-collector/src/xsscollector/scope.py:87) only checks URL scope and resolves addresses; it never evaluates the setting or address classification. [Configuration](F:/projects/XSSBOSS/xssboss-collector/src/xsscollector/config.py:17) also defaults it to true. The HTTP layer discards the returned address list before opening a connection. **Modify:** make the private-network policy effective and explicit, deny destinations outside the intended network boundary by default, and enforce the validated destination at the transport boundary, including redirects. Use mocked resolver and transport tests to prove that a disabled permission is actually enforced.

12. **P1 — The headline 100% result is a small simulation, not measured application accuracy.** The [README result](F:/projects/XSSBOSS/README.md:67) comes from five cases. Its [execution check](F:/projects/XSSBOSS/benchmarks/benchmark_fuzzer_efficacy.py:85) uses pattern matching, not browser execution. The [guided benchmark](F:/projects/XSSBOSS/benchmarks/benchmark_fuzzer_efficacy.py:223) directly receives the fixture's true context and filter rules, which are not equally supplied to the baseline. This supports a narrow component experiment, not an end-to-end comparison. The [readiness scorecard](F:/projects/XSSBOSS/docs/READINESS_SCORECARD.md:17) separately lists only three negative browser cases. **Modify:** label component simulations clearly, separate them from browser and full-system evaluation, and publish case counts, uncertainty, error counts, versions, and test conditions. Retire unsupported universal success and readiness scores.

13. **P1 — The false-positive benchmark can pass when its own machinery fails.** [Simulation errors](F:/projects/XSSBOSS/benchmarks/benchmark_false_positive.py:201) return a negative result; [generation errors](F:/projects/XSSBOSS/benchmarks/benchmark_false_positive.py:274) become an empty list. The [gate](F:/projects/XSSBOSS/benchmarks/benchmark_false_positive.py:232) passes whenever its false-positive count is zero. A broken evaluation can therefore appear reassuring. **Modify:** represent evaluation errors, untested cases, and completed negatives as distinct states. Require expected cases to complete valid checks before calculating a passing outcome. Add fault-injection tests using mocks, without making network requests.

14. **P2 — Accuracy scoring silently accepts malformed or incomplete result sets.** [The metric calculator](F:/projects/XSSBOSS/backend_api/quality/accuracy.py:24) collapses duplicate IDs into dictionaries, ignores predictions outside the truth set, and converts arbitrary values using Python truthiness. For example, a nonempty string is not a valid boolean measurement. Only missing expected IDs affect completeness. **Modify:** strictly validate booleans, unique IDs, exact expected/predicted membership, supported completion states, and schema version before scoring. Reject duplicate or unexpected records rather than silently discarding them.

15. **P2 — A nonempty summary can produce a “confirmed” finding label.** For non-XSS classes, [result serialization](F:/projects/XSSBOSS/backend_api/services/result_service.py:968) uses `bool(finding.evidence_summary)` as sufficient verification. That proves a summary exists; it does not independently prove the relevant claim. **Modify:** define class-specific, typed evidence requirements and distinguish observed behavior, analyst confirmation, and runtime verification. A summary should describe the evidence and its limits, not serve as the confirmation mechanism. Non-browser findings need their own appropriate proof criteria rather than a universal browser requirement.

16. **P2 — Expired worker ownership is not checked consistently before completion.** [Lease completion](F:/projects/XSSBOSS/backend_api/services/test_case_lease_service.py:82) clears ownership without checking the claim's owner or attempt, and its fallback update filters by row ID alone. [Worker completion](F:/projects/XSSBOSS/browser_workers/worker.py:959) also changes the row directly. A delayed process could overwrite a newer claim after reassignment. By contrast, the synthetic scale probe has an ownership predicate, so its passing result does not validate every production completion path. **Modify:** enforce current ownership and claim generation atomically for lifecycle changes, reject stale completions, and respect cancellation. Verify this with inert jobs and database tests; no scanning is needed to exercise job ownership.

17. **P2 — Retention can lose the information needed to finish deleting private data.** [Retention](F:/projects/XSSBOSS/backend_api/services/retention_service.py:49) commits database deletion before unlinking artifact files. A file error or crash after that commit can leave files behind after their tracked records are gone. [Tenant selection](F:/projects/XSSBOSS/backend_api/services/retention_service.py:21) excludes inactive tenants, and diagnostic logs are outside the experiment ownership cascade. **Modify:** persist a retryable deletion manifest before removing ownership records, reconcile orphaned artifacts, include inactive tenants under an explicit retention policy, and cover original screenshots, reports, and logs as well as content-addressed copies. Keep dry-run and auditable completion states.

18. **P2 — Live diagnostics are incomplete across processes and have inconsistent authentication.** [The ring buffer](F:/projects/XSSBOSS/backend_api/services/log_service.py:46) exists separately in each process, while [SSE](F:/projects/XSSBOSS/backend_api/services/log_service.py:272) subscribes only to the current process. Events from separate Celery workers will not automatically reach that connection. The UI's [EventSource](F:/projects/XSSBOSS/ui/src/pages/LogsPage.tsx:172) does not carry the bearer header added by its [Axios wrapper](F:/projects/XSSBOSS/ui/src/utils/request.ts:16). **Modify:** use a tenant-scoped durable event source with stable cursors and authenticated streaming. Define replay, disconnection, and gap behavior. Do not solve streaming authentication by restoring the shared-key proxy issue in finding 1.

19. **P2 — CI does not reproducibly prepare or cover all declared checks.** The [unit job](F:/projects/XSSBOSS/.github/workflows/quality.yml:17) runs all root tests without installing Playwright browsers. [Root tests](F:/projects/XSSBOSS/tests/test_benchmark_suite.py:102) include a real browser benchmark unless an opt-out variable is set. Browser installation in a different job does not prepare this job. Root `pytest.ini` limits discovery to `tests/`, and the workflow does not separately run the collector suite. UI lint is also absent from the workflow. **Modify:** explicitly separate browser and pure unit jobs, install prerequisites in each applicable job, run collector checks, and enforce lint. Treat missing prerequisites as setup failures. The missing setup is verified in configuration; the predicted hosted failure was not reproduced in this audit.

20. **P2 — Request metrics use unbounded user-controlled route groups.** [Route grouping](F:/projects/XSSBOSS/backend_api/main.py:39) takes a path segment directly and stores it in process-wide dictionaries, including for rejected or unknown requests. Unique paths can continually add metric series and consume memory. The same value is interpolated into the text exporter. **Modify:** label metrics with a fixed set of registered route templates and a single unmatched bucket, use proper metric escaping, and bound retained dimensions. Validate exporter output and cardinality with harmless synthetic paths.

**What to build next, in order**

| Stage | Concrete deliverable | Completion condition |
|---|---|---|
| 1. Deployment boundary | Visitor authentication, enforced tenant logging, token revocation, narrow CORS, minimal image contents, dependency updates, worker isolation, effective collector network policy | Unauthenticated and cross-tenant access is rejected in isolated regression tests; image inventory excludes private files; affected dependency advisories are resolved |
| 2. Evidence contract | Versioned, typed observation and confirmation records; shared redaction; explicit invalid/inconclusive states; reliable deletion | Every displayed confirmation satisfies its class-specific evidence contract; every exported artifact records its policy and provenance; failed evaluations cannot pass |
| 3. Independent evaluation | Versioned controlled fixtures separated into development and untouched evaluation sets; negative controls; evaluation manifests | Results identify source revision, dependency and browser versions, fixture versions, case counts, errors, exclusions, precision, recall, false-positive rate, and confidence intervals |
| 4. Operator reliability | Consistent lifecycle ownership, authenticated event replay, bounded metrics, separated CI jobs | Inert-job recovery, cancellation, event completeness, and deployment checks pass on the exact release revision |
| 5. Maintainability | Smaller API handlers and UI components, reusable policies, explicit module interfaces | Changes to authentication, evidence, or results have one authoritative implementation and independently testable boundaries |

Measure precision (`TP / (TP + FP)`), recall (`TP / (TP + FN)`), false-positive rate (`FP / (FP + TN)`), and evaluation completion separately. Include independent review disagreement and incomplete-run counts. A run that could not complete is not a clean negative. An observed result on a small fixture set is not a demonstrated rate across other applications.

The current accuracy function's 98% precision and 95% recall thresholds are policy choices, not established performance. Confidence intervals and sufficiently independent cases are needed before making statements about those rates. Bug-bounty acceptance also depends on scope, duplicate status, program policy, impact, and human assessment; this repository cannot establish that outcome from scanner hits alone.

For more advanced engineering, prioritize typed evidence contracts, privacy-preserving exports, provenance, reproducible evaluation, and independent review. Freeze additional adaptive or AI complexity until its contribution can be assessed in controlled evaluation without changing the outcome criteria. This audit does not recommend payload evasion improvements or autonomous exploitation enhancements.

Large files are a maintenance signal: the audit counted over 2,000 nonblank lines in `ScanPage.tsx` and over 1,000 in several backend and worker modules. Split them by stable responsibilities after defining behavior and contracts. Also replace the fixed repository test database and session-end wipe in [test fixtures](F:/projects/XSSBOSS/tests/conftest.py:13) with per-run temporary isolation before adding parallel test execution.

Keep the existing useful foundations: production configuration refusal, scoped artifact lookup with hash verification, the safer default that does not bypass CSP, a working TypeScript build, and the existing focused tests. They provide places to strengthen the system, but their presence does not cancel the gaps identified above.
